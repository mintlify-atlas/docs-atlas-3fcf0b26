The PR Quiz workflow is a self-contained GitHub Actions automation that embeds multiple-choice questions directly into pull request descriptions. When a reviewer opens the PR, they see a set of questions about the code changes. The workflow watches for answers — either via checkbox ticks in the description or a `/answer` comment — and grades them automatically, posting the result as a commit status. A PR cannot be considered fully reviewed until a qualified participant answers every question correctly.

## How answering works

Reviewers have two ways to submit answers:

**Option 1 — Tick checkboxes in the PR description.** The quiz block renders each question with lettered options as GitHub-flavoured Markdown checkboxes. Reviewers tick one box per question directly in the PR body. The workflow detects the change on the `edited` event and grades automatically.

```markdown
**1. What does the Mutex in CachingQuoteRepository prevent?**
- [ ] **A)** UI recompositions
- [x] **B)** Duplicate concurrent API calls
- [ ] **C)** SharedPreferences race conditions
- [ ] **D)** ViewModel leaks
```

**Option 2 — Post a `/answer` comment.** Anyone eligible can post a comment whose first line starts with `/answer` followed by space-separated `<question><letter>` pairs. All questions must be covered in a single comment.

```
/answer 1B 2A 3C
```

## Commit status lifecycle

The workflow maintains a single commit status under the `pr-quiz` context. It moves through three states:

| State | When it appears |
|---|---|
| `pending` | The quiz was found but not all questions have been answered yet, or a reviewer ticked multiple options for one question. |
| `failure` | All questions were answered but at least one answer was wrong. The bot posts explanations in a collapsible block. |
| `success` | Every answer is correct. The pass is recorded in a hidden comment marker so it survives new commits. |
